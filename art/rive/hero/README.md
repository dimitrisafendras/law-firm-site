# Hero animation

One native Rive artboard, driven by the looping `Ambient` state machine:

- Mesh: small illuminated facets with independent, smooth brightness cycles.
  A canonical cyan-material mask rejects marble and preserves transparent holes
  across the identically framed statue variants.
- Performance: detailed geometry and masking are baked into cropped 2× textures
  at build time. The WebGL2 runtime animates only 24 lighting groups and draws
  25 body image layers, rather than thousands of independently animated shapes.
  The 24-second loop combines different phases and harmonics to avoid lockstep.
- Fire: two eight-second upward-flowing turbulent texture sequences generated by
  `scripts/hero-fire.mjs`, blended in Rive. Each uses 240 small frames (30 fps); only the
  two adjacent frames per pan are visible. No noise or fluid simulation runs
  in the browser. The digital pan burns blue; the brass pan burns warm gold.
- No Matrix rain or star layers. Small CSS particles drift behind the statue.
- Sparse exterior facets drift toward the digital silhouette and fade out.
  Their trajectories are checked against the photo alpha to avoid marble.

`npm run build:hero-rive` regenerates the editable RML, verifies/inspects it,
and exports `public/animations/hero.riv`. Requires the Rive CLI. Ordinary site
builds use the checked-in binary and do not require Rive or an account.

Edit `scripts/build-hero-rive.mjs` for reproducible changes, or open this project
with `rive art/rive/hero`. The generated scene uses no embedded scripts.

The photograph remains the CSS-selected transparent asset. The animation never
fills the original holes, replaces the photograph, or adds floating stars.
On the existing cropped mobile hero the animation is disabled. Reduced-motion
users see the static original; hidden and offscreen desktop scenes pause.
